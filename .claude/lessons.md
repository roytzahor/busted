- [2026-07-25] [eval] `run-fixtures.ts` replays the STORED `detectedStorePriceUsd` from `scrape.json`, so a fix to `lib/scraping/extract-price.ts` shows a 0.000 eval delta until the fixtures are backfilled by re-running the extractor over the already-captured `raw.markdown`. Backfill nulls only — synthetic fixtures' non-null prices are hand-authored to build a specific markup scenario and must not be FX-recomputed.
- [2026-07-25] [scraping] Price extraction on he-IL Shopify has four traps, all found in real captures: the `₪` sits AFTER the number as often as before it and is separated by bidi marks (U+200E/200F), the cart total renders BEFORE the product so testing only the first regex match let one `0 ₪` disqualify the whole pattern, the compare-at price precedes the sale price so "first labelled number" overstates markup (prefer `מחיר מבצע`/`במבצע`), and a free-shipping banner (`משלוח חינם מעל ₪399`) reads as a product price. Threshold/cart context must be matched in a window that stops at the previous price or punctuation — a flat lookback also rejects the real price, and generic `סך הכל` means "total REVIEWS" on Remora.
- [2026-07-25] [ai] `gemini-2.5-flash` is a thinking model and thinking tokens are drawn from `maxOutputTokens`, so a small cap silently truncates the ANSWER — `translate-title.ts` had 40, spent ~35 on thoughts, and returned `finishReason=MAX_TOKENS` on 100% of calls ("totwoo Smart jewelry" → "tot"). Length guards can't catch this; gate on `finishReason === MAX_TOKENS` and set `thinkingConfig.thinkingBudget: 0` for mechanical tasks (also ~4× cheaper than merely raising the cap).
- [2026-07-25] [eval] The fixture corpus cannot measure RETRIEVAL — `aliexpress.json` is a stored candidate pool, so any fix to keywords/translation/search shows a 0.000 eval delta and an unchanged `mean titleOverlap` by construction, even when correct. Measure such fixes on the derived artifact (`extractSearchKeywords` output) plus unit tests; treat the eval only as a no-regression gate. Several real fixtures' pools were captured with the broken keywords ("encrypted", "tot", raw Hebrew) and are unrelated products — that, not a blind text arm, is why real `titleOverlap` sits at 0.041.
- [2026-07-25] [ui] The film grain is `.dark body::after` at `z-index: 100` — it must stay above every app layer (highest in use is the recent-scans drawer at `z-[70]`, nav is `z-50`), so any new overlay above 100 will sit outside the texture and look detached. - [2026-07-27] [ui] Room tokens are not paper tokens: `--success` is tuned for the dark ground and measures 1.6:1 on `--paper` (invisible), which is why `--paper-money` exists. Assume every room colour fails on paper until measured, and measure by converting oklch to *linear* RGB and feeding the WCAG luminance formula directly — running the sRGB transfer function over already-linear values double-converts and fabricates failures (it wrongly flagged `--muted-foreground` at 2.9:1 when it is actually 8.2:1).
- [2026-07-25] [session] Only `lib/track.ts` MINTS the `busted_session_id_v1` session uuid; `lib/feedback.ts`, `lib/clicks.ts` and `lib/error-reporter.ts` read it and fall back to the shared constants `"no-session"`/`"no-storage"`/`"ssr"` — so a real id exists only because `AnalyticsMount` fires `page_view` from the layout first. - [2026-08-25] [ui] `tw-animate-css` defines `--animate-in` as `enter <dur> var(--tw-ease, ease)`, so an `animate-in` with no `ease-*` class animates on plain `ease` — which ramps IN at the exact moment the user is watching. All 15 entry animations were doing this. Always pair `animate-in` with `ease-out`, and set the house curve by overriding the STOCK Tailwind tokens (`--ease-out`, `--default-transition-timing-function`) rather than adding a parallel `--ease-house` nobody remembers to use.
- [2026-08-25] [a11y] The blanket `prefers-reduced-motion` reset (`transition-duration: 0.01ms !important` on `*`) also kills the opacity and colour transitions that carry meaning, so every state change teleports. - [2026-08-25] [ui] An `oklch()` token can name a colour OUTSIDE sRGB, and the browser silently clamps it — so the rendered colour is not the specified one, and a P3 display may not clamp identically. `--stamp` (C 0.24) needed G_linear = -0.014 and `--paper-money` (C 0.16) needed R_linear = -0.037; both are now pinned to 0.22/0.10. Check gamut (convert to linear RGB, assert every channel in [0,1]) BEFORE measuring contrast, or you are measuring a colour the CSS does not actually specify.
